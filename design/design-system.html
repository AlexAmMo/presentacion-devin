    01

    Color

    Cinco colores de marca hacen todo el trabajo: navy para el contenido y rojo para el foco. Las cremas son el suelo y el blanco separa las superficies. Los tres rojos son el mismo rojo según el fondo, así que cuentan como un único acento. Cada muestra es la variable tal como está en design-system.css, con su valor final y su descripción.

    Semántica en uso

    Sobre navy (.inverso)

    Por qué no hay más tonos: la paleta se ciñe a la marca y los conceptos se distinguen por la luminosidad (oscuro, medio, hueco) y por la forma (sólido, rayado, contorno, continuo o discontinuo). Así siguen legibles con el proyector lavado y para personas con daltonismo. El precio: acierto y fallo de caché no tienen color propio; se separan por el trazo y el icono.

    Contraste, calculado con las variables

    Los pares salen solos de los nombres: --color-sobre-X con --color-X, cada -borde con el fondo y los tres textos con fondo y superficies; más unos pocos pares fijos.

    07

    Reglas

    Principios visuales

    Son del design system y no están en CLAUDE.md. Las reglas de trabajo (colores, cómo ampliar el sistema, cámara) se leen de CLAUDE.md, más abajo; si algo chocara, manda CLAUDE.md.

    • Un solo acento por pantalla. El rojo marca lo que hay que mirar ahora: la zona actual, el nivel de llenado o la cifra protagonista. Nunca hay dos elementos rojos a la vez.
    • El rojo según el fondo: sobre claro, sobre navy y solo dentro del logo. Los logos de design/assets/logos/ nunca se recolorean.
    • Toda superficie lleva contorno navy de . El proyector iguala crema y blanco; el tono por sí solo no separa nada.
    • Nada por debajo de a 1920×1080. Contraste de texto de al menos 4,5:1; 3:1 solo para texto de 24 px o más y para gráficos.
    • Sin decoración: nada de partículas, brillos, destellos, degradados, sombras difusas ni giros 3D decorativos. Hasta la herramienta que se da la vuelta lo hace en plano.
    • Cada concepto, un único dibujo: se dibuja una vez en componentes.css y las escenas lo reutilizan. Un token es siempre una píldora en DM Mono; la caché, siempre un corchete.
    • Ningún dato inventado: las cifras de ejemplo se marcan en la propia escena con «Cifras ficticias»; las reales llevan su nota de fuente.
    • Iconos Lucide con stroke-width 2: por defecto (trazo real de 3 px, igual que el contorno), dentro de etiquetas y para el icono principal de una pieza grande (agente, skill, herramienta).

    09

    Uso en código

    La presentación (Vite, JavaScript sin framework) importa las mismas fuentes que esta página. Nada se copia: si cambia una variable, un componente o un efecto, cambia aquí y en la presentación a la vez.

    Importar

    // src/main.js · el orden importa: primero las variables
import '../design/design-system.css';   // variables y fuentes locales
import '../design/componentes.css';     // el vocabulario visual
import { gsap } from 'gsap';            // desde npm, incluido en el build
import { v, s, px, esEstatico } from '../design/motion.js';   // al importarse registra los efectos
import { icono, pintarIconos } from '../design/iconos.js';
import { grafica, dial, temporizador, circuito, bucle, curva } from '../design/dibujos.js';

    Usar los efectos en una escena

    // Coreografía de una sola escena: encadena efectos; tiempos solo con s() y v().
const tl = gsap.timeline();
tl.apilarCapa('.e09 .capa')
  .subirNivel('.e09 .nivel', { y: -354 }, `+=${s('--pausa-lectura-corta')}`)
  .atenuar('.e09 .capa:not(.relevante)');

// Una cifra: formato español y dígitos tabulares.
gsap.effects.subirContador('.total', { hasta: 0.43, decimales: 2 });

    Contrato de los efectos

    1. Se registran en motion.js con gsap.registerEffect({ …, extendTimeline: true }): funcionan sueltos (gsap.effects.nombre) y como método de un timeline (tl.nombre(objetivos, opciones, posición)).
    2. Se nombran con un verbo en infinitivo y van precedidos de un comentario /** … */ que esta página muestra como descripción.
    3. Sus valores por defecto se leen de las variables cada vez que se llaman. Las opciones que se pasen ganan, pero nunca son duraciones ni curvas literales: se pasan con s() y v(). Las distancias en px sí pueden ir literales.
    4. Devuelven su tween o timeline y animan solo dentro de su zona: ningún efecto mueve la cámara.
    5. Se pueden rebobinar: los cambios de clase se hacen con tl.set(…, { attr: { class } }) y nunca en callbacks, así que retroceder o saltar hacia atrás no deja estados colgados.
    6. En modo estático (?estatico, prefers-reduced-motion o data-movimiento="estatico" en <html>) duran 0 y saltan a su estado final.
    7. Un efecto nuevo lleva en el mismo cambio: su registro, su demo en doc/documentacion.js y su nombre en la línea movimiento: de los componentes que lo usan. Si falta algo, «Comprobaciones» lo marca.

    Ejecutar y exportar

    • npm install una vez, con conexión. Después todo funciona sin ella.
    • npm run dev: servidor de Vite. Esta página está en http://localhost:5173/design/design-system.html.
    • npm run build:design: esta página como un único HTML autocontenido en dist-design/design/design-system.html, con código, CSS, fuentes e imágenes dentro. Se abre con doble clic.
    • La presentación (index.html) tendrá su propio build de un solo fichero; se añade en el esqueleto.
    • DESIGN.md, en la raíz, es un resumen derivado para Impeccable: se regenera con /impeccable document cuando cambia design/ y nunca se edita a mano.

    Ampliar el sistema

    • Variable: en su grupo de design-system.css, en una sola línea y con su descripción en un comentario. Las curvas dicen con qué duración van (· con --dur-…). Aparece sola en esta página.
    • Componente: un bloque en componentes.css con su cabecera (clase, forma, color, medidas, icono, movimiento, escenas) y su muestra en doc/laminas.js. Si necesita geometría SVG, va en dibujos.js.
    • Icono: npm run iconos -- nombre.
    • Efecto: ver el contrato.

    Ficheros: design/design-system.css, componentes.css, motion.js, iconos.js, dibujos.js, assets/fonts/ (Outfit y DM Mono, OFL), assets/logos/ (logos oficiales), assets/licencias/ (Lucide, ISC) y doc/ (solo esta página). ronda-1-direcciones.html es la exploración inicial de direcciones: histórico, no es referencia.
